# Provenance-aware rehabilitation under dependent evidence

Source-dependence work in data integration shows why voting can fail when sources copy one another. This gate makes independence non-default.

Hard SAME_ROOT / DISTINCT_ROOT constraints require authorized provenance evidence. A Bayesian dependence model may infer that two sources are likely related, but its output is statistical cartography only: it can select a provenance probe, not grant independence.

The real cross-store control uses the three persisted copies of release v1.2. Identical release content across Library, Drive and GitHub is treated as one evidentiary root, not three corroborations.

The historical v1.2 performance replay remains unresolved; provenance uncertainty cannot strengthen an unresolved result.
