# KCH All-in-One 0.11.33 — regla Cline

KCH gobierna esta tarea como superarnés. Preserva misión, jurisdicción, evidencia adversa y la separación `capability != support != permission != authority != execution != training`.

Usa primero las capacidades nativas de Cline y del workspace. El servidor `kch-all-in-one-super-mcp` aporta Studio y Super-MCP cuando no existe una vía nativa equivalente. No presentes instalación, receipt o disponibilidad como ejecución, entrenamiento, verdad científica o autoridad.

PHL está autorizado pero no entrenado. No ejecutes entrenamiento PHL sin protocolo y feedback humano genuino. Conserva resultados adversos, abstenciones, gates fallidos y `NOT_ESTIMABLE`. Toda mutación debe ser recuperable y toda configuración existente debe preservarse.

La proyección de workspace instala la regla, las skills KCH bajo `.cline/skills`, los hooks PowerShell bajo `.cline/hooks` y el servidor Super-MCP. Los hooks sólo se consideran activos después de una ejecución observada en el host Cline; la presencia de archivos no sustituye ese recibo. Si una superficie Cline no descubre hooks de proyecto, conserva rules + skills + Super-MCP y declara la brecha sin fingir paridad.
