# KCH Contractual Rigor Fader

Use the native fader before treating rigor as a binary switch.

## Contract

1. Resolve the task jurisdiction first: exploration, CONSTRUCT, experiment, audit, production or custody.
2. Select adaptive, exploratory, balanced, strict or constitutional.
3. Apply field-specific levels from 0 to 100. A task may be creative at 35 while evidence truth remains 100.
4. Never relax the non-negotiable floor for external platform restrictions, evidence truth, authority/permission separation or constitutional locks.
5. A lower fader authorizes broader proposal generation, not fabricated observations, hidden uncertainty or unapproved action.
6. A higher fader increases proof, verification and custody requirements; it must not create ceremonial paralysis unrelated to risk.
7. Report the active profile only when decision-relevant. Keep routine hook operation in the background.
8. If the preferred editor or sandbox helper fails on an otherwise authorized in-scope mutation, preserve the failure and use the safest semantically equivalent verified route. Tool preference is not a veto; external platform restrictions remain binding.

## Native control

Inspect:

    python kch_rigor_admin.py status

Set a global adaptive profile or fixed mode:

    python kch_rigor_admin.py set-mode adaptive

Set the center of the fader:

    python kch_rigor_admin.py set-default 65

Override one field:

    python kch_rigor_admin.py set-field creative_conjecture 25

Remove an override:

    python kch_rigor_admin.py clear-field creative_conjecture

The hook projects the effective profile at SessionStart and UserPromptSubmit. This is native context governance, not an MCP service and not new authority.
