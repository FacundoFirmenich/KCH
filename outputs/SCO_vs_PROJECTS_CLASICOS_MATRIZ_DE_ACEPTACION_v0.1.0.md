# SCO frente a Projects clásicos — matriz de aceptación v0.1.0

Esta matriz fija la interpretación vinculante usada para construir SuperChats Orquestadores (SCO). “Projects clásicos” designa el patrón de contenedor con instrucciones, archivos, memoria o contexto compartidos; no una versión concreta de un producto.

| Dimensión | Projects clásicos | SCO |
|---|---|---|
| Unidad dominante | El proyecto o contenedor | Cada chat/tarea soberano; SCO es una capa externa |
| Agrupación | Carpeta o pertenencia común | Grafo explícito de nodos elegidos |
| Contexto | Compartido, heredado o inyectado | Nativo e independiente; divulgación mínima por contrato |
| Memoria | Común o sustituida por memoria de proyecto | Memoria nativa preservada; memoria orquestal separada |
| Identidad | Subordinada al proyecto | URI, proveedor, historia, función y jurisdicción intactas |
| Autonomía | Instrucción global relativamente uniforme | Nivel tipado por nodo, desde observación hasta suborquestación acotada |
| Funciones | Chats paralelos frecuentemente redundantes | Fuente, ejecutor, crítico, revisor, adjudicador, monitor, integrador |
| Coordinación | Manual o basada en contexto común | Aristas, dependencias, condiciones, gates y recibos |
| Sinergia | Yuxtaposición | Producción encadenada y causalmente trazable |
| Transferencia | Texto copiado o resumen informal | Referencias y fragmentos hashados expresamente autorizados |
| Herramientas | Denominador común del contenedor | Capacidades nativas independientes por nodo |
| Proveedores | Normalmente un ecosistema | Codex, ChatGPT, Cline, Cowork, OpenCode y adaptadores futuros |
| Autoridad | Global o implícita | Capacidad distinta de permiso; techo por nodo y orden |
| Desacuerdo | Síntesis, sobrescritura o último mensaje | Divergencia conservada hasta adjudicación explícita |
| Resultados adversos | Tendencia a subsumirlos en el resultado final | `FAILED`, `BLOCKED` y `ABSTAINED` preservados por separado |
| Fallos | Pueden contaminar el proyecto entero | Aislamiento y retiro no destructivo de nodos |
| Ciclo de vida | Dependencia del contenedor | Entrada, retiro y bifurcación sin destruir la tarea nativa |
| Planificación | Lista lineal | Grafo parcialmente ordenado y ciclos visibles |
| Escala | Más chats implican más ruido contextual | Activación selectiva según función y dependencia |
| Observabilidad | Actividad visible con causalidad débil | Ledger de quién produjo, transformó, revisó y autorizó |
| Exportación | Corpus o documento agregado | Grafo portable sin historias ni memorias nativas |
| Relación con KCH | Contenedor externo | Componente KCH con preset y lowering CSI |
| Claim verificable | “Los chats están juntos” | “Están orquestados” sólo si selección, aislamiento, ruteo, autoridad y recibos pasan gate |

## Antiobjetivos vinculantes

1. No crear un megacontexto mediante copia de conversaciones.
2. No sustituir memorias nativas por una memoria central.
3. No fingir conectores vivos donde sólo existe referencia.
4. No confundir texto con ejecución, evidencia o autoridad.
5. No imponer a todos los nodos el mismo prompt, modelo mental, herramientas o autonomía.

## Criterio de superioridad

La v0.1.0 demuestra propiedades arquitectónicas más explícitas y fuertes: soberanía, aislamiento, separación de autoridad, causalidad y preservación de divergencias. No demuestra todavía mejor calidad, coste o velocidad de resultados que Projects: eso requiere una campaña comparativa prerregistrada.
