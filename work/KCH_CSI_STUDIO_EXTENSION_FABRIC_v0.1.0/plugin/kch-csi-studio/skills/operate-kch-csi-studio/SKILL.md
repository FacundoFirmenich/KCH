# Operate KCH CSI Studio

1. Inspect `kch_next_status`, `constitution_effective`, and `programmed_policy_status` first. The precedence is the user constitution, then the programmed DIRECT rules, then the four-way consultation gate. A model may propose constitutional changes but never enact them.
2. Keep PLAN, RUN, and CONSTRUCT distinct. CONSTRUCT writes a versioned successor, validates it, backs up the stable version, and only promotes it for the next start; never overwrite the active runtime in place.
3. For CSI construction, call `studio_create_session`, `studio_generate`, `studio_validate`, and `studio_seal` in order. Preserve jurisdiction, inputs, outputs, authority ceiling, host targets, and type-specific metadata.
4. Treat search, recommendation, download, installation, enablement, authentication, first execution, and operational authority as distinct gates. Use the four decisions `YES`, `NO`, `NEVER_THIS_SESSION`, and `ALWAYS_THIS_SESSION` for consultative execution.
5. Use structured persistence for ordinary traceability. Before a full checkpoint, call `checkpoint_estimate`, show the disk warning, and obtain explicit confirmation. Never equate a checkpoint with external-host completeness without an EOF/transport receipt.
6. KwanData structures and tags information while retaining exact source custody. KwanDocs remains the separate canonical evidence-authority workflow.
7. MIS calculations and certificates create neither authority nor execution. Its current CSI lowering is bounded to four instructions. Preserve the negative claim boundary.
8. Account permission leases must be finite. Never embed credentials. Microphone monitoring is off at startup and requires explicit user activation with visible indication and a consent basis.
